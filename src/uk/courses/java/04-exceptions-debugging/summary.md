# Підсумки

## Висновки

Обробник повинен знаходитися там, де можна надати змістовну реакцію. Передумови перевіряють до зміни стану, ресурси закривають автоматично, а причину не гублять під час перетворення винятку.

## Питання для самоперевірки

1. Чим checked відрізняється від unchecked?
2. Чому підтип catch має бути перед надтипом?
3. Які типи можна об’єднати через multi-catch?
4. Чим throw відрізняється від throws?
5. Чому finally не є гарантією при аварії процесу?
6. Чому небезпечний return у finally?
7. Як зберегти початкову причину винятку?
8. У якому порядку закриваються ресурси?
9. Чим suppressed відрізняється від cause?
10. Чому assert не перевіряє користувацький ввід надійно?
11. Який стан треба переглянути для помилки середнього?
12. Як перевірити незмінність стану після відмови?
