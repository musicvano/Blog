# Підсумки

## Висновки

Інваріант визначає допустимий стан об’єкта. Конструктор встановлює інваріант до початку використання. Композиція керує життям вкладених значень. Мінімальний інтерфейс полегшує перевірку.

## Питання для самоперевірки

1. Чим клас відрізняється від конкретного об’єкта?
2. Чому перевірку слід виконувати до зміни поля?
3. У якому порядку ініціалізуються поля?
4. Що відбувається, якщо конструктор кидає виняток?
5. Коли потрібен explicit-конструктор?
6. Яку обіцянку дає const-метод?
7. Для чого існують this і mutable?
8. Чим статичне поле відрізняється від звичайного?
9. Що належить до заголовка, а що до .cpp?
10. Коли struct доцільніший за інкапсульований class?
11. Чому setter для кожного поля може погіршити інтерфейс?
12. Що рахує лічильник created у прикладі замовлення?
13. Як перевірити відмову без зміни стану?
14. Чому unique_ptr усуває потребу в ручному delete?
15. Які правила має призначена ініціалізація агрегату?
