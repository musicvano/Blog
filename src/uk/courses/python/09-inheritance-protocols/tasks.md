# Завдання

Відповідно до номера свого варіанта виконайте завдання обраного рівня складності.

Усі рівні потребують UML-діаграми класів із напрямками наслідування або реалізації, сигнатурами й анотаціями. Для Protocol поясніть, чому клас відповідає йому без явного наслідування; для ABC покажіть відмову створення неповного класу. У високому рівні передбачте іменовані CLI-параметри та повторювані `--item` для записів із документованими полями, `--help` і клавіатурне меню без аргументів. Помилки йдуть у stderr із кодом 2, успіх – із кодом 0. Виводьте поліморфну таблицю і підсумки. Усі ставки, ціни й норми умов задач навчальні. Жодні повідомлення, платежі чи запити не надсилаються назовні.

## Порядок виконання та захисту роботи

1. Опишіть спільний контракт: передумови, результат, одиниці й очікувані винятки. Намалюйте UML до реалізації.
2. Оберіть ABC для спільної основи або Protocol для незалежних реалізацій. Не створюйте ієрархію лише заради одного поля.
3. Реалізуйте типізовані класи та поліморфний цикл без ланцюжка перевірок конкретних типів. Спільну ініціалізацію викликайте через `super` там, де цього потребує контракт.
4. Застосуйте однакові контрактні перевірки до всіх реалізацій: звичайні дані, межі, відмови та тип результату.
5. Для MRO або міксина, якщо вони потрібні у варіанті, перевірте порядок і одноразовість кроків. Для Protocol не обмежуйтеся лише `isinstance`.
6. Подайте UML, код, README, таблицю щонайменше п’яти перевірок та локальну історію Git; UML звірте з остаточним кодом.
7. На захисті додайте новий підклас або реалізацію протоколу, не змінюючи цикл звіту, і поясніть принцип підстановки.
