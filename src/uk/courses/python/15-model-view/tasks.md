# Завдання

Відповідно до номера свого варіанта виконайте завдання обраного рівня складності.

Використовуйте Python 3.14 і PySide6. Для SQLite оберіть Qt SQL або власну модель над репозиторієм SQLAlchemy, якщо завдання не визначає конкретного шляху. Не підтримуйте два незалежні буфери редагування тих самих записів. Ціни й суми зберігайте цілими копійками; дати – ISO `YYYY-MM-DD`.

## Варіанти

### Варіант 1. Облік витрат {#v1}

**1. Початковий рівень.** Створити графічний застосунок PySide6 «Облік витрат» для навчальних записів (id, дата, категорія, `сума_коп`). Дані задати в коді; реалізувати QTableView над QStandardItemModel, показати суму витрат. Порожній набір показувати без помилки.

**2. Базовий рівень.** Створити графічний застосунок PySide6 «Облік витрат» із записами (id, дата, категорія, `сума_коп`), QTableView над QStandardItemModel, показати суму витрат; додати діалог додавання з додатною сумою, делегат дати та фільтр категорії через проксі. Помилки пояснювати у вікні, Cancel залишає попередні дані без змін.

**3. Високий рівень.** Створити графічний застосунок PySide6 «Облік витрат» із записами (id, дата, категорія, `сума_коп`), QTableView над QStandardItemModel, показати суму витрат та діалог додавання з додатною сумою, делегат дати та фільтр категорії через проксі; реалізувати SQLite з ручним збереженням пакета, скасуванням і експортом видимого фільтра CSV; перевірити rollback при неправильній сумі. Додати pytest-перевірки моделі й тимчасової бази, включаючи неправильний запис, Cancel і відкат; зберігати дані після перезапуску й не губити незбережені зміни мовчки.

## Порядок виконання та захисту роботи

1. Визначте сутності, стабільні id, стовпці, ролі, правила редагування та зв’язки таблиць. Підготуйте лише навчальні дані.
2. Реалізуйте модель і перевірте читання, допустиме редагування, відмову без зміни стану та сигнали вставлення/видалення.
3. Додайте представлення, пошук і сортування. Окремо перевірте `mapToSource` після зміни порядку й фільтра.
4. Реалізуйте діалоги з валідацією та Cancel. Перед зміною стану перевіряйте весь запис або пакет імпорту.
5. Для бази перевірте commit, rollback, повторний запуск, зовнішні ключі й незбережені зміни. Для CSV – заголовок, кодування, неправильний рядок та недоступний шлях.
6. Для високого рівня додайте pytest-тести моделі й репозиторію з тимчасовою базою; offscreen-тести доповніть оглядом вікна. Збережіть код, схему, README, результати й скриншот форми.
7. На захисті поясніть, хто володіє даними, моделлю, діалогом і транзакцією, та покажіть відмову без часткової зміни.
