# Підсумки

## Висновки

Структури є типами-значеннями: присвоєння копіює всі поля, тому вони підходять для невеликих незмінних значень, а `readonly struct` запобігає помилкам зі зміною копій. Приведення структури до `object` чи інтерфейсу виконує упакування. Записи генерують рівність значень, `ToString`, копіювання виразом `with` і деконструкцію; `record class` – посилальний тип, `record struct` – тип-значення. Перелічення замінюють «магічні числа» іменованими константами, а `[Flags]` дозволяє зберігати набори значень у бітах; разом із виразом `switch` вони реалізують скінченні автомати. Кортежі групують кілька значень без оголошення типу й зручні для повернення кількох результатів з методу; деконструкція та позиційні шаблони спрощують роботу з ними.

## Питання для самоперевірки

1. Чим структура відрізняється від класу?
2. Що відбувається під час присвоєння змінної структури?
3. Які значення мають поля `default` структури? Чи викликається конструктор?
4. Коли слід обирати структуру замість класу?
5. Що таке `readonly struct`? Чому змінні структури небезпечні?
6. Що таке упакування й розпакування? Коли воно відбувається для структур?
7. Які члени компілятор генерує для запису?
8. Як працює рівність записів?
9. Для чого призначений вираз `with`?
10. Чим `record struct` відрізняється від `readonly record struct`?
11. Який базовий тип і які значення мають константи перелічення за замовчуванням?
12. Як безпечно розібрати рядок у значення перелічення?
13. Як оголосити й використовувати перелічення-прапорці?
14. Що таке кортеж? Як дати імена його елементам?
15. Що таке деконструкція? Як реалізувати її для власного класу?
16. Що таке позиційний шаблон і шаблон властивостей?
