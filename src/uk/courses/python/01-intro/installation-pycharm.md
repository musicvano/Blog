# Встановлення Python і PyCharm

## Встановлення Python

### Windows: менеджер встановлення

Основна платформа практикуму – Windows 11. Відкрийте <https://www.python.org/downloads/windows/> і встановіть **Python Install Manager**. Не плутайте менеджер із самим середовищем виконання: він завантажує й обслуговує потрібні версії Python. Команди менеджера описано на <https://docs.python.org/3.14/using/windows.html>.

::: info Знімок екрана
python.org/downloads/windows: Install Manager and Python 3.14
:::

Рис. 1.3. Завантаження Python для Windows {.caption}

Після встановлення відкрийте новий PowerShell і виконайте:

```powershell
py install 3.14
py list
py -V:3.14 --version
python --version
where.exe python
```

`py list` показує встановлені версії, а `where.exe` – знайдені виконувані файли. У PowerShell слід писати саме `where.exe`, оскільки коротке `where` має інше значення. Якщо `py install` не розпізнано, можливо, запускається старий Python Launcher: використайте `pymanager install 3.14` і перевірте джерело команди. Не вилучайте наявні інтерпретатори, доки не з’ясуєте, які проєкти їх потребують.

::: info Знімок екрана
PowerShell: py install 3.14; py list; python –version
:::

Рис. 1.4. Перевірка встановленого Python 3.14 {.caption}

Класичний `.exe`-інсталятор ще трапляється для Python 3.14, але позначений як застарілий; для 3.16 і новіших його не планують випускати. Прапорець *Add python.exe to PATH* стосується саме цього інсталятора. Якщо команда відкриває Microsoft Store, перевірте *App execution aliases* та шлях до потрібного Python; не змінюйте навмання всі системні аліаси.

::: info Знімок екрана
python: `2 ** 100`; import sys; sys.version; exit()
:::

Рис. 1.5. Інтерактивний сеанс Python {.caption}

### Linux і macOS

У Linux системний `python3` може мати іншу версію, ніж потрібна для курсу. Не замінюйте ним системні компоненти. У Debian/Ubuntu модуль створення середовищ може потребувати окремого пакета:

```bash
python3 --version
sudo apt update
sudo apt install python3-venv
python3 -m venv .venv
source .venv/bin/activate
```

Ці команди використовують версію дистрибутива. Якщо потрібна саме 3.14, після встановлення uv за офіційною інструкцією виконайте `uv python install 3.14`, потім `uv venv --python 3.14 .venv` у новому каталозі проєкту. Не запускайте обидві команди створення над одним наявним середовищем без потреби.

У macOS можна встановити `.pkg` з <https://www.python.org/downloads/macos/>. Перевірте `python3.14 --version`; середовище створіть командою `python3.14 -m venv .venv`. Після активації `source .venv/bin/activate` команда `python` має вказувати на середовище проєкту. В обох системах пакети проєкту встановлюйте без `sudo pip`.

## Середовище JetBrains PyCharm

**IDE** (*Integrated Development Environment*) поєднує редактор, запуск, налагоджувач і засоби керування проєктом. PyCharm не замінює Python: IDE запускає вибраний інтерпретатор. Завантаження: <https://www.jetbrains.com/pycharm/download/>.

PyCharm тепер постачається як єдиний продукт. Базові можливості залишаються безкоштовними; після пробного періоду Pro можна продовжувати роботу з ними. Для цієї лабораторної платні можливості не потрібні. Освітні умови перевіряйте окремо: <https://www.jetbrains.com/academy/student-pack/>. Не вважайте студентську ліцензію дозволом на будь-яке комерційне використання.

Для PyCharm 2026.2 документація вказує 8 ГБ загальної оперативної пам’яті, 3 ГБ вільної для IDE, 10 ГБ дискового простору та екран від 1280×720. Java окремо встановлювати не потрібно: JetBrains Runtime входить до постачання. Актуальні вимоги: <https://www.jetbrains.com/help/pycharm/installation-guide.html>.

::: info Знімок екрана
PyCharm download: Windows, version and download button
:::

Рис. 1.6. Сторінка завантаження PyCharm {.caption}

Встановіть IDE безпосередньо або через JetBrains Toolbox App. Під час першого запуску оберіть англійський інтерфейс, щоб назви команд збігалися з матеріалом. Імпорт старих налаштувань необов’язковий. У вікні привітання можна створити проєкт, відкрити каталог або клонувати репозиторій (рис. 1.7).

### Перший проєкт

1. Натисніть *New Project* та оберіть *Pure Python*.
2. Укажіть каталог `C:\Labs\hello`; назва проєкту відповідає назві каталогу.
3. Оберіть *Project venv* і базовий Python 3.14. Середовище буде в `.venv`.
4. Створіть `main.py` через *New → Python File*. Якщо IDE вже створила приклад, замініть його наведеним нижче кодом.
5. Для першого запуску натисніть правою кнопкою по файлу та *Run 'main'*. Після створення конфігурації її можна повторно запустити **Shift+F10**.

::: info Знімок екрана
New Project: Pure Python; hello; Project venv; Python 3.14
:::

Рис. 1.8. Проєкт із власним середовищем {.caption}

```py
"""Перша програма курсу."""


def main():
    print("Hello, Python!")


if __name__ == "__main__":
    main()
```

Результат програми:

```
Hello, Python!
```

У вікні *Run* IDE додатково показує команду запуску та код завершення. `Process finished with exit code 0` означає успішне завершення процесу, але не доводить правильності обчислень. Перевіряйте також сам результат. Проєкт створюється за інструкцією <https://www.jetbrains.com/help/pycharm/creating-empty-project.html>.

::: info Знімок екрана
main.py; Project; Run with Hello, Python!; interpreter widget
:::

Рис. 1.9. Редактор і результат запуску {.caption}

Вікно *Project* показує файли, *Run* – результат окремого процесу, *Python Console* – інтерактивний Python, а *Terminal* – командну оболонку. Команду `python main.py` вводять у терміналі, не після `>>>`. Для форматування коду використовуйте **Ctrl+Alt+L**, для підказки виправлення – **Alt+Enter**, для документації – **Ctrl+Q** у стандартній розкладці Windows. Перепризначені клавіші перевіряйте в *Settings → Keymap*.

## Структура модуля і помилки

**Модуль** – файл із Python-кодом. На початку доречний рядок документації (*docstring*), далі – імпорти, визначення функцій і точка запуску. `def main():` визначає функцію, але не виконує її. Виклик `main()` запускає її тіло. Перевірка `__name__ == "__main__"` відрізняє прямий запуск від імпорту: під час імпорту визначення завантажаться без цього виклику.

Відступи утворюють блоки. Використовуйте чотири пробіли на рівень, а не суміш пробілів і табуляції. Коментар починається із символу `#` і пояснює задум. Назви змінних і функцій пишіть у `snake_case`, констант – у `UPPER_CASE`. Правила стилю: <https://peps.python.org/pep-0008/>.

Навмисно замініть `print` на `prnt` і запустіть файл. У **traceback** знайдіть останній рядок із типом помилки, а вище – файл і номер рядка. `NameError` означає невідоме ім’я; підказка редактора не є автоматичним виправленням. Виправте помилку і повторіть запуск, щоб переконатися в результаті.

::: info Знімок екрана
prnt("Hi"); Run: NameError and clickable source line
:::

Рис. 1.10. Читання повідомлення про помилку {.caption}

Таблиця 1.2. Перші помилки та напрям пошуку причини {.caption}

| **Помилка** | **Приклад причини** | **Що перевірити** |
| --- | --- | --- |
| `SyntaxError` | Пропущено `:` після `def` | Синтаксис указаного рядка |
| `IndentationError` | Немає відступу в тілі функції | Чотири пробіли на рівень |
| `NameError` | `prnt` замість `print` | Написання і визначення імені |
| `ModuleNotFoundError` | Пакет у іншому середовищі | Шлях інтерпретатора |

### Приклад: аргументи командного рядка

Файл `args.py` показує, як оболонка передає дані програмі. Це інший спосіб введення, ніж `input`: значення задаються до запуску процесу.

```py
"""Показує аргументи без їх перетворення."""
import sys

print("Файл:", sys.argv[0])
print("Аргументи:", sys.argv[1:])
```

Запуск `python args.py alpha "beta gamma"` дає:

```
Файл: args.py
Аргументи: ['alpha', 'beta gamma']
```

Лапки об’єднують два слова в один аргумент і зазвичай не входять до його значення. У PyCharm відкрийте *Run → Edit Configurations* і запишіть ці значення в поле параметрів скрипту. Перевірте також *Working directory*: від нього залежать відносні шляхи. Не додавайте аргументи до тексту імені файла.
