# Ресурси, тема та розповсюдження

## Ресурси, тема та попередній перегляд

У KMP-проєкті ресурси розташовують у `composeResources`. Генерований `Res.string` чи `Res.drawable` дає типізований доступ; потрібний модуль Compose resources. У звичайному JVM-модулі також можна працювати з classpath-ресурсами, але не слід підміняти їх шляхом до файла вихідного проєкту.

Темна й світла палітри мають зберігати контраст. Повідомлення про помилку передають текстом, а не лише кольором рамки. Поле повинно мати зрозумілий label, кнопка – дієслівний підпис. Клавіатурна навігація й видимий фокус важливі для desktop.

`@Preview` допомагає оглядати невеликий компонент із заданими параметрами без повної навігації. Підтримка preview залежить від IDE й плагінів; відсутня панель не означає, що програма не компілюється. Для preview передавайте демонстраційні дані, а не запускайте справжню базу або мережу.

Compose Hot Reload прискорює перевірку змін UI у підтримуваній конфігурації. Він не замінює чисту компіляцію, тести чи повторний запуск із порожнім станом. Підключайте плагін за поточним офіційним посібником, узгоджуючи його версію з проєктом: <https://kotlinlang.org/docs/multiplatform/compose-hot-reload.html>.

## Перевірка та розповсюдження

Перевірка має три рівні. Звичайний модульний тест перевіряє формули та валідацію без Compose. Тест стану перевіряє переходи після подій. UI-тест або ручний сценарій перевіряє доступність кнопок, текст помилки, фокус, прокручування та зміну розміру. Успішна компіляція не підтверджує читабельність графічного екрана.

Для desktop Compose надає задачі пакування, зокрема `packageDistributionForCurrentOS`. Формат інсталятора залежить від ОС і налаштованих `nativeDistributions`: пакет для Windows готують на Windows із потрібними інструментами пакування. `mainClass`, назва пакета, версія та включені JVM-модулі мають бути визначені до складання інсталятора.

Не записуйте робочі дані в теку встановлення. Ресурси програми можуть бути лише для читання; особистий каталог користувача або обраний шлях підходить для бази й налаштувань. Пакет перевіряють запуском з іншої робочої теки, на чистому профілі та повторним відкриттям збережених даних.
