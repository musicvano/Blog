# Підсумки

## Висновки

MVVM робить стан і події явними, навігація керує історією, а репозиторій ізолює збереження. Надійність визначається також поведінкою при помилці: чернетка не губиться, UI не блокується, скасування поширюється, успіх підтверджується після транзакції.

## Питання для самоперевірки

1. Чому ViewModel не повинна знати NavController?
2. Коли collectAsState припиняє збирати потік?
3. Чому в маршруті передають id замість повного об’єкта?
4. Чим відрізняється помилка форми від одноразового повідомлення?
5. Що перевіряє fake-репозиторій і чого він не перевіряє?
6. Чому перезапуск інстальованої програми є окремою перевіркою?
