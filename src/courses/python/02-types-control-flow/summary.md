# Summary

## Conclusions

A Python name refers to an object with its own type. Numeric calculations require the right choice of type, units, and rounding rule. Input starts as text, so conversion and validation must be explicit. Branches determine the execution path, while loops let you apply an algorithm to a series of values without duplicating code.

## Self-check questions

1. What changes when a name is reassigned?
2. How do `==` and `is` differ?
3. What precision limitations do `int` and `float` have?
4. Why does `0.1 + 0.2 == 0.3` return false?
5. When should you use integer kopiykas or Decimal?
6. Why is `bool("False")` true?
7. How does `//` for negative numbers differ from truncation?
8. How does short-circuit evaluation protect against division by zero?
9. How does format validation differ from range validation?
10. When can several `if` statements not be replaced with an `elif` chain?
11. What does a bare name after `case` mean?
12. Which numbers does `range(8, 1, -3)` specify?
13. When does a loop's `else` run?
14. Why can a series minimum not always start at zero?
15. What reference data do you need to test every branch?
