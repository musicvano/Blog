# Завдання

Відповідно до номера свого варіанта виконайте завдання обраного рівня складності.

Програми C# у завданнях невеликі: головне – історія їх розробки в Git. Усі завдання виконуються з локальними репозиторіями, без облікового запису GitHub і доступу до мережі.

## Варіанти

### Варіант 1. Список покупок {#v1}

**1. Початковий рівень.** Створити консольну програму C# «Список покупок», яка виводить товари з кількістю, і вести її історію в локальному репозиторії Git: створити `.gitignore` командою `dotnet new gitignore`, зробити щонайменше чотири коміти зі змістовними повідомленнями (створення проєкту, виведення списку, додавання товару з клавіатури, підрахунок позицій) і показати історію командою `git log --oneline`.

**2. Базовий рівень.** Створити консольну програму C# «Список покупок» (товари з кількістю та ціною) у локальному репозиторії Git і розробити в гілках `feature/remove` (видалення товару) і `feature/total` (підрахунок вартості) по два коміти; злити першу гілку в `main` перемотуванням (fast-forward), а другу – тристороннім злиттям після нового коміту в `main`, видалити злиті гілки, позначити результат анотованим тегом `v1.0` і показати `git log --oneline --graph --all` та `git show v1.0`.

**3. Високий рівень.** Створити консольну програму C# «Список покупок» (товари з кількістю) і організувати її командну розробку без хостингу: створити порожній репозиторій `D:\Labs\remote\Shopping.git`, надіслати в нього `main` і зробити другий клон від імені іншого учасника (власні `user.name` і `user.email` у клоні). Кожен учасник розробляє свою функцію (сортування, збереження списку у файл) в окремій гілці та надсилає її, а інший переглядає гілку командами `git log main..origin/<гілка>` і `git diff main...origin/<гілка>` і зливає. Отримати та розв’язати один конфлікт злиття, позначити випуск тегом `v1.0` з файлом `CHANGELOG.md` і показати граф історії в обох клонах та `git ls-remote --tags origin`.

### Варіант 2. Бібліотечний формуляр {#v2}

**1. Початковий рівень.** Створити консольну програму C# «Бібліотечний формуляр» (видані читачеві книги та дати їх повернення) і зафіксувати її розробку в локальному репозиторії Git щонайменше десятьма невеликими комітами, кожен з яких залишає проєкт у стані, що збирається; показати історію командами `git log --oneline` і `git log --stat -3`.

**2. Базовий рівень.** Створити консольну програму C# «Бібліотечний формуляр» (видані читачеві книги та дати їх повернення) у репозиторії Git, створити гілку `feature/overdue` (пошук прострочених книг) з двома комітами, тим часом додати в `main` коміт з іншою зміною, перебазувати гілку командою `git rebase main`, злити її перемотуванням і показати, що історія лінійна (`git log --oneline --graph`), а хеші комітів гілки змінилися.

**3. Високий рівень.** Створити консольну програму C# «Бібліотечний формуляр» (видані книги та дати повернення) у репозиторії Git і підготувати її випуски за правилами семантичного версіювання: розробити в окремих гілках виправлення помилки, нову функцію та зміну формату виведення, перед злиттям перебазовувати кожну гілку на актуальний `main`, після кожного злиття доповнювати `CHANGELOG.md` і ставити анотовані теги `v1.0.0`, `v1.0.1`, `v1.1.0`; створити архів випуску командою `git archive --format=zip -o Library-1.1.0.zip v1.1.0` і показати `git tag -n`, `git log --oneline --graph --decorate` та `git diff --stat v1.0.0 v1.1.0`.

### Варіант 3. Облік витрат {#v3}

**1. Початковий рівень.** Створити консольну програму C# «Облік витрат», яка підсумовує витрати за категоріями, у репозиторії Git; закомітити помилкову зміну (неправильний підсумок), скасувати її командою `git revert` і показати командами `git log --oneline` та `git show`, що історія зберегла обидва коміти.

**2. Базовий рівень.** Створити консольну програму C# «Облік витрат» (підсумок витрат за категоріями) у репозиторії Git, створити дві гілки, які по-різному змінюють рядок виведення підсумку, злити їх у `main`, отримати конфлікт і розв’язати його в терміналі (видалити маркери, об’єднати зміни), перевірити збірку й завершити злиття; показати `git status` під час конфлікту та `git log --oneline --graph` після злиття.

**3. Високий рівень.** Створити консольну програму C# «Облік витрат» (підсумок витрат за категоріями) і змоделювати роботу двох учасників з порожнім репозиторієм `D:\Labs\remote\Expenses.git` і двома клонами: обидва змінюють обчислення підсумку, другий отримує відмову `git push` (`rejected`), виконує `git pull`, розв’язує конфлікт у редакторі злиття Visual Studio 2026 і надсилає результат. Потім знайти опублікований помилковий коміт, скасувати його командою `git revert` без переписування історії, вести `CHANGELOG.md` і показати граф історії обох клонів.

### Варіант 4. Розклад дзвінків {#v4}

**1. Початковий рівень.** Створити консольну програму C# «Розклад дзвінків», яка виводить час початку й кінця пар, у репозиторії Git; почати зміну тривалості перерви, сховати незавершену роботу командою `git stash`, виправити й закомітити помилку в назві пари, повернути зміни командою `git stash pop` і завершити їх окремим комітом. Показати `git stash list` і `git log --oneline`.

**2. Базовий рівень.** Створити консольну програму C# «Розклад дзвінків» (час початку й кінця пар) у репозиторії Git і розробити в гілках `feature/short-day` (скорочений день) і `feature/next-bell` (час до наступного дзвінка) дві функції: під час роботи над першою сховати зміни з повідомленням (`git stash push -m`), завершити другу, повернутися й відновити схованку; злити обидві гілки й поставити анотований тег `v1.0`. Показати `git log --oneline --graph --all` і `git tag -n`.

**3. Високий рівень.** Створити консольну програму C# «Розклад дзвінків», що читає час пар із файлу, у репозиторії Git і організувати її випуски: гілки функцій, теги `v1.0.0` і `v1.1.0`, дві незалежні незавершені зміни в схованці, застосовані вибірково (`git stash apply "stash@{1}"`). Після випуску `v1.1.0` виправити помилку в гілці `hotfix/1.1.1`, створеній від тегу (`git switch -c hotfix/1.1.1 v1.1.0`), злити її в `main`, поставити тег `v1.1.1` і доповнити `CHANGELOG.md`. Показати граф історії, теги та `git diff v1.1.0 v1.1.1`.

### Варіант 5. Щоденник погоди {#v5}

**1. Початковий рівень.** Створити консольну програму C# «Щоденник погоди» (температури за тиждень і середнє значення) у репозиторії Git із файлами `.gitignore` і `.gitattributes`, створеними шаблонами `dotnet new`, зробити кілька комітів і показати командою `git ls-files --eol`, що текстові файли зберігаються в індексі з кінцями рядків LF.

**2. Базовий рівень.** Створити консольну програму C# «Щоденник погоди» (температури за тиждень і середнє значення) у репозиторії Git, зробити щонайменше вісім комітів, в одному з яких непомітно внести помилку в обчислення середньої температури; знайти цей коміт командою `git bisect`, позначаючи версії `good` і `bad` після запуску програми, показати його зміни командою `git show` і скасувати помилку командою `git revert`.

**3. Високий рівень.** Створити консольну програму C# «Щоденник погоди» з методом обчислення мінімуму, максимуму й середнього значення температур, створити її історію з 15 і більше комітів із прихованою помилкою, написати сценарій перевірки, який запускає програму з відомими даними й повертає код 0 для правильного результату, і знайти помилковий коміт автоматично командою `git bisect run`. Показати `git bisect log`, автора рядка з помилкою (`git blame -L`), виправити помилку в гілці `fix/average` і злити її.

Показати граф історії та `git branch -a` в обох клонах.

Високий рівень.** Створити консольну програму C# «Трекер тренувань» (тренування та сумарний час) у репозиторії Git і підтримувати дві лінії її випусків: гілку `release/1.x`, створену від тегу `v1.0.0`, і `main` для версії 2. Показати `git log --oneline --graph --all`, повідомлення перенесеного коміту та `git branch --contains` для виправлення.
