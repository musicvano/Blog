# Завдання

Відповідно до номера свого варіанта виконайте завдання обраного рівня складності.

## Варіанти

### Варіант 1. Щоденник подій {#v1}

**1. Початковий рівень.** Створити самостійний desktop-застосунок Kotlin/Compose «Щоденник подій»: список, деталі, редагування, SQLite через Exposed. Реалізувати список та додавання основної сутності через ViewModel зі StateFlow, а дані надати репозиторієм у пам’яті. Користувач вводить назву й предметне поле, бачить новий рядок або помилку; UI не змінює MutableStateFlow напряму.

**2. Базовий рівень.** Створити самостійний desktop-застосунок Kotlin/Compose «Щоденник подій»: список, деталі, редагування, SQLite через Exposed. Реалізувати список, деталі й форму редагування з типобезпечним id маршруту, ручним передаванням репозиторію Exposed/SQLite та валідацією ViewModel. Після успішного запису оновлювати список, при помилці зберігати чернетку; невідомий id показувати явно. Перевірити Back, Cancel і повторне відкриття файлу.

**3. Високий рівень.** Створити самостійний desktop-застосунок Kotlin/Compose «Щоденник подій»: список, деталі, редагування, SQLite через Exposed. Побудувати MVVM із репозиторієм-інтерфейсом, SQLite-реалізацією, маршрутами списку/деталей/редагування та станами loading/data/error. Реалізувати предметний звіт, транзакційну складену дію й захист від повторного натискання. Додати `--db=path`, `--help`, `--report=from:to` для звіту без GUI: вирівняна таблиця та підсумки, помилки до stderr, коди 0/2/1. Написати тести ViewModel із fake і SQLite-тести відкату, ключів та міграції; перевірити збереження після перезапуску.

1. Визначити маршрути, UiState та предметний інтерфейс репозиторію.
2. Передати залежності через конструктори; не створювати БД в UI.
3. Виконувати JDBC поза Main, зберігати чернетку при помилці.
4. Перевірити невідомий id, повернення, повторне натискання й збій БД.
5. Запустити тести ViewModel із fake та інтеграційні тести SQLite.
6. Перевірити збереження після перезапуску й описати шлях до даних.
