# Завдання

Відповідно до номера свого варіанта виконайте завдання обраного рівня складності.

Основна СКБД – SQLite. Початковий рівень використовує `sqlite3`; базовий додає зв’язки й звіти; високий реалізує предметний доступ через SQLAlchemy 2.0 і обов’язкові тести pytest. Alembic є додатковим дослідженням, а не заміною обов’язкових вимог. Шлях до окремого навчального файла бази передавайте аргументом. Меню має додавати, показувати, змінювати й видаляти записи за ідентифікатором із підтвердженим результатом операції. Для деструктивних дій використовуйте тільки базу цієї лабораторної. Грошові суми зберігайте цілими копійками, дати – у перевіреному ISO-форматі. Особові дані вигадані. Усі функції мають анотації.

## Варіанти

### Варіант 1. Бібліотека {#v1}

**1. Початковий рівень.** Створити консольний застосунок sqlite3 із таблицею `books(id,title)`. Шлях SQLite-файла передавати аргументом, записи вводити через меню. Реалізувати додавання, читання за id, зміну й видалення; id є INTEGER PRIMARY KEY, текстові назви непорожні, суми невід’ємні цілі копійки, дати ISO, інші числові поля невід’ємні. Вивести впорядкований за id список і повідомлення про відмову. Використати параметри, анотовані функції та явні commit/rollback.

**2. Базовий рівень.** Створити консольний застосунок для SQLite зі схемою `books(id,title)`; `readers(id,name); loans(id,book_id,reader_id,due,returned)`. id є PK, поля з суфіксом \_id є FK до відповідної сутності; ключі зв’язків без id складені. Шлях бази передавати аргументом, початкові записи вводити через меню. Реалізувати CRUD та звіт: відкриті позики з due раніше дати ISO, переданої аргументом; returned є 0 або 1. Текстові назви непорожні, суми цілі копійки; задати NOT NULL, CHECK і потрібні UNIQUE. Вивести детальний звіт зі стабільним сортуванням. Використати sqlite3, увімкнути зовнішні ключі до транзакції, параметризовані запити й один JOIN з агрегатом або підзапитом. Пов’язаний пакет змін виконати атомарно й довести відкат при помилці.

**3. Високий рівень.** Створити консольний застосунок для SQLite зі схемою `books(id,title)`; `readers(id,name); loans(id,book_id,reader_id,due,returned)`. id є PK, поля з суфіксом \_id є FK до відповідної сутності; ключі зв’язків без id складені. Шлях бази передавати аргументом, початкові записи вводити через меню. Реалізувати CRUD та звіт: відкриті позики з due раніше дати ISO, переданої аргументом; returned є 0 або 1. Текстові назви непорожні, суми цілі копійки; задати NOT NULL, CHECK і потрібні UNIQUE. Вивести детальний звіт зі стабільним сортуванням. Реалізувати доступ через SQLAlchemy 2.0: DeclarativeBase, Mapped, relationship та select; сесія й транзакція мають явного власника, зв’язки для звіту завантажити без зайвого N+1. Обов’язкові pytest на окремій базі для успіху, дубля, неправильного FK/межі та rollback пакета. Показати SQL звіту й перевірити відповідність результату ручному обчисленню.
