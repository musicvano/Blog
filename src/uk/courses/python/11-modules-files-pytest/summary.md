# Підсумки

## Висновки

Модулі й пакети задають межі відповідальності. Формат файла є зовнішнім контрактом: потрібно перевіряти не лише синтаксис, а й предметний зміст. Відокремлені обчислення та явні шляхи дозволяють перевіряти програму швидко й безпечно в тимчасових каталогах.

## Питання для самоперевірки

1. Який код виконується під час першого імпорту?
2. Чим `sys.modules` відрізняється від `sys.path`?
3. Для чого потрібна умова з `__name__`?
4. Як відносний імпорт залежить від способу запуску?
5. Чим робочий каталог відрізняється від каталогу модуля?
6. Які режими відкриття можуть змінити файл?
7. Чому кодування потрібно вказувати явно?
8. Що JSON втрачає при перетворенні кортежу або dataclass?
9. Навіщо перевіряти структуру після `json.loads`?
10. Чому CSV не можна надійно розділити через `split`?
11. Що перевіряє `pytest.raises`?
12. Як `parametrize` впливає на кількість тестів?
13. Які гарантії ізоляції дає `tmp_path`?
14. Коли корисні `capsys` і `monkeypatch`?
15. Чому 100 відсотків покриття не доводять правильності?
