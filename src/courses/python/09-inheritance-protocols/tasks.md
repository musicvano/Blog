# Tasks

Complete the task of the chosen difficulty level for your variant number.

All levels require a UML class diagram with inheritance or implementation directions, signatures, and annotations. For Protocol, explain why a class satisfies it without explicit inheritance; for ABC, demonstrate rejection of instantiating an incomplete class. At the advanced level, provide named CLI parameters and repeatable `--item` records with documented fields, `--help`, and a keyboard menu when no arguments are given. Errors go to stderr with code 2, success with code 0. Print a polymorphic table and totals. All rates, prices, and norms in the task specifications are for learning purposes. No messages, payments, or requests are sent externally.

## Procedure

1. Describe the shared contract: preconditions, result, units, and expected exceptions. Draw UML before implementation.
2. Choose ABC for a shared base or Protocol for independent implementations. Do not create a hierarchy just for one field.
3. Implement typed classes and a polymorphic loop without a chain of concrete type checks. Call shared initialization through `super` where the contract requires it.
4. Apply the same contract checks to all implementations: ordinary data, boundaries, rejections, and result type.
5. For MRO or a mixin, if required by the variant, verify the order and that each step runs exactly once. For Protocol, do not limit checks to `isinstance`.
6. Submit UML, code, a README, a table of at least five checks, and local Git history; compare the UML with the final code.
7. During the defense, add a new subclass or protocol implementation without changing the report loop, and explain the substitution principle.
